ĐỀ TÀI LAB AN NINH THÔNG TIN

Xây dựng hệ thống cân bằng tải và dự phòng cho dịch vụ ứng dụng, cơ sở dữ liệu và tường lửa nhằm nâng cao tính sẵn sàng và an toàn dịch vụ

1. Lý do chọn đề tài

Trong các hệ thống dịch vụ trực tuyến hiện nay, yêu cầu về tính liên tục, ổn định và an toàn ngày càng trở nên quan trọng. Nếu một thành phần trong hệ thống gặp sự cố như máy chủ web bị lỗi, cơ sở dữ liệu ngừng hoạt động hoặc tường lửa bị hỏng, toàn bộ dịch vụ có thể bị gián đoạn. Điều này ảnh hưởng trực tiếp đến người dùng và có thể gây mất an toàn thông tin.

Để giảm thiểu rủi ro, các hệ thống thực tế thường sử dụng cơ chế cân bằng tải và dự phòng. Cân bằng tải giúp phân phối yêu cầu của người dùng đến nhiều máy chủ khác nhau, trong khi cơ chế failover cho phép hệ thống tự động chuyển sang thành phần dự phòng khi có sự cố. Bên cạnh đó, tường lửa là lớp bảo vệ quan trọng, cũng cần được thiết kế dự phòng để tránh điểm lỗi đơn.

Vì vậy, đề tài này được xây dựng nhằm mô phỏng một hệ thống hoàn chỉnh gồm firewall, load balancer, web server và database có khả năng chịu lỗi, đồng thời áp dụng các nguyên tắc bảo mật cơ bản trong an ninh thông tin.

2. Mục tiêu đề tài

2.1. Mục tiêu tổng quát

Xây dựng và vận hành được hệ thống lab có khả năng cân bằng tải, dự phòng cho dịch vụ ứng dụng, cơ sở dữ liệu và tường lửa. Hệ thống cần đảm bảo hoạt động ổn định khi một thành phần gặp sự cố, đồng thời đáp ứng các yêu cầu cơ bản về bảo mật.

2.2. Mục tiêu cụ thể

  • Hiểu được mô hình mạng nhiều vùng: WAN, DMZ, LAN/Database.
  • Biết cấu hình firewall để kiểm soát truy cập giữa các vùng mạng.
  • Triển khai load balancer để phân phối tải đến nhiều web server.
  • Triển khai cơ chế failover cho load balancer hoặc firewall.
  • Cấu hình database replication giữa primary và replica.
  • Kiểm thử hệ thống khi một dịch vụ hoặc một máy chủ gặp sự cố.
  • Nắm được các nguyên tắc bảo mật cơ bản: firewall rule, phân tách mạng, log, hardening dịch vụ.

3. Phạm vi thực hiện

3.1. Phạm vi nên làm

  • Xây dựng lab trên máy ảo bằng VirtualBox, VMware hoặc Proxmox.
  • Triển khai firewall pfSense hoặc OPNsense.
  • Triển khai load balancer bằng HAProxy hoặc Nginx.
  • Triển khai 2 web server.
  • Triển khai 2 node database theo mô hình primary - replica.
  • Cấu hình firewall rule, NAT và kiểm soát truy cập.
  • Kiểm thử load balancing, failover web server, replication database.
  • Thu thập log và giám sát trạng thái cơ bản.

3.2. Phạm vi mở rộng

  • Failover load balancer bằng Keepalived.
  • Failover firewall bằng pfSense CARP hoặc OPNsense CARP.
  • Giám sát bằng Prometheus, Grafana hoặc Zabbix.
  • Bảo mật nâng cao bằng Fail2Ban, Suricata hoặc WAF.
  • Triển khai HTTPS bằng chứng chỉ self-signed hoặc Let’s Encrypt.

7. Yêu cầu chức năng

7.1. Firewall

  • Cho phép truy cập HTTP/HTTPS từ WAN vào load balancer.
  • Chặn truy cập trực tiếp từ WAN vào database.
  • Cho phép web server truy cập database theo port cần thiết.
  • Ghi log lưu lượng bị chặn và được phép.
  • Hỗ trợ NAT/port forwarding.

7.2. Load Balancer

  • Phân phối request đến ít nhất 2 web server.
  • Kiểm tra trạng thái web server bằng health check.
  • Tự động loại bỏ server lỗi khỏi pool.
  • Có thể cấu hình Virtual IP để client truy cập một địa chỉ duy nhất.

7.3. Web Server

  • Hoạt động tối thiểu trên 2 node.
  • Có thể kết nối database.
  • Hiển thị thông tin nhận dạng server để kiểm tra load balancing.
  • Có log truy cập.

7.4. Database

  • Có ít nhất 2 node: primary và replica.
  • Dữ liệu được đồng bộ từ primary sang replica.
  • Kiểm tra được dữ liệu trên replica sau khi ghi trên primary.
  • Có thể mô phỏng failover bằng cách tắt primary và kiểm tra replica.

8. Yêu cầu bảo mật

  • Chỉ mở các port cần thiết.
  • Phân tách mạng WAN, DMZ và LAN/Database.
  • Không cho phép truy cập trực tiếp từ WAN vào database.
  • Giới hạn quyền truy cập SSH.
  • Sử dụng mật khẩu mạnh hoặc SSH key.
  • Cấu hình firewall theo nguyên tắc tối thiểu.
  • Ghi log hệ thống, log firewall và log dịch vụ.

10. Cấu hình HAProxy mẫu

global
    log /dev/log local0
    log /dev/log local1 notice
    maxconn 4096

defaults
    log global
    mode http
    option httplog
    option dontlognull
    timeout connect 5s
    timeout client 30s
    timeout server 30s

frontend http_front
    bind *:80
    default_backend web_backend

backend web_backend
    balance roundrobin
    option httpchk GET /
    server web1 192.168.20.21:80 check
    server web2 192.168.20.22:80 check

listen stats
    bind *:8404
    stats enable
    stats uri /stats
    stats refresh 10s

11. Kịch bản kiểm thử hệ thống

Kịch bản 1: Kiểm tra load balancing web server

Mục tiêu: Chứng minh request được phân phối đến nhiều web server.

Các bước:

  1. Client truy cập địa chỉ VIP hoặc IP load balancer.
  2. Tải lại trang nhiều lần.
  3. Quan sát kết quả hiển thị Web Server 1 hoặc Web Server 2.

Kết quả mong đợi: Request được phân phối luân phiên hoặc theo thuật toán đã cấu hình.

Kịch bản 2: Kiểm tra web server lỗi

Mục tiêu: Chứng minh load balancer tự loại bỏ server lỗi.

Các bước:

  1. Tắt dịch vụ web trên Web Server 1.
  2. Truy cập lại dịch vụ.
  3. Kiểm tra trạng thái trong HAProxy stats.

Kết quả mong đợi: Dịch vụ vẫn hoạt động, request chỉ được gửi sang Web Server 2.

Kịch bản 3: Kiểm tra replication database

Mục tiêu: Chứng minh dữ liệu từ primary được đồng bộ sang replica.

Các bước:

  1. Tạo database và bảng trên primary.
  2. Insert dữ liệu vào primary.
  3. Kiểm tra dữ liệu trên replica.

Kết quả mong đợi: Replica có dữ liệu giống primary.

Kịch bản 4: Kiểm tra database primary lỗi

Mục tiêu: Mô phỏng sự cố database primary.

Các bước:

  1. Tắt dịch vụ database trên primary.
  2. Kiểm tra ứng dụng có còn đọc được dữ liệu từ replica không.
  3. Nếu có cấu hình failover, promote replica thành primary.

Kết quả mong đợi: Replica vẫn có dữ liệu và có thể được sử dụng để tiếp tục vận hành.

Kịch bản 5: Kiểm tra bảo mật bằng firewall rule

Mục tiêu: Chứng minh hệ thống chặn truy cập trái phép.

Các bước:

  1. Từ client WAN, thử truy cập trực tiếp database.
  2. Kiểm tra kết quả.
  3. Xem log firewall.

Kết quả mong đợi: Không truy cập được database từ WAN, firewall ghi log truy cập bị chặn.

14. Hướng phát triển

  • Triển khai HTTPS với chứng chỉ số.
  • Thêm WAF để bảo vệ ứng dụng web.
  • Thêm Suricata/Snort làm IDS/IPS.
  • Dùng Patroni hoặc ProxySQL để failover database tự động hơn.
  • Thêm hệ thống giám sát tập trung bằng Prometheus và Grafana.
  • Thêm backup và restore database.
  • Mô phỏng tấn công DDoS và kiểm thử khả năng chịu tải.

15. Kết luận

Đề tài giúp xây dựng một hệ thống lab hoàn chỉnh mô phỏng kiến trúc dịch vụ có khả năng chịu lỗi và bảo mật. Hệ thống bao gồm firewall kiểm soát truy cập giữa các vùng mạng, load balancer phân phối tải đến các máy chủ ứng dụng, cụm web server xử lý yêu cầu người dùng và cụm cơ sở dữ liệu có cơ chế đồng bộ, dự phòng.

Thông qua quá trình triển khai, người thực hiện có thể nắm vững các kiến thức về mạng máy tính, quản trị hệ thống, cấu hình dịch vụ, cân bằng tải, failover, replication và các biện pháp bảo mật liên quan. Đây là nền tảng quan trọng đối với sinh viên ngành An ninh thông tin trong việc tiếp cận các hệ thống thực tế có yêu cầu cao về tính sẵn sàng và an toàn dịch vụ.
